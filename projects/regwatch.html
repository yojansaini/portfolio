Problem

During SecurePay's PA transition and payin revamp, staying current with RBI and NPCI regulatory output became unsustainable. The process was entirely manual. Someone had to find the circular, read it, assess relevance, and flag it to the right person.

With 10–15 circulars issued daily across both regulators, this wasn't a time problem. It was a risk problem: a missed requirement landing in a live feature spec or a PPI application filing. Generic tools returned too much noise and understood nothing about fintech regulatory context.

The insight was that compliance monitoring was being treated as a research task when it needed to be a system.

My role

I identified the problem, defined the product, and built it entirely myself: frontend, backend, crawler pipeline, RAG architecture, LLM fine-tuning, and AWS deployment. No engineering support. RegWatch is a solo build driven by a product need I lived firsthand as PM on the PA transition.

What I built

Crawler layer. Automated Python crawlers scraping RBI and NPCI sources on a scheduler, feeding a structured SQLite alerts database. A Python queue with three automatic retry attempts handles crawl failures, with a manual retry trigger for persistent cases.

The NPCI crawler was the hardest part of the build. NPCI's website uses dynamic client-side rendering, so most scraping approaches fail outright. Getting reliable automated extraction required working around the rendering layer entirely. The kind of detail you only know if you built it yourself.

RAG pipeline. ChromaDB vector store with sentence-transformers for semantic retrieval. Summary regeneration triggers automatically on generation failure or on an explicit request for deeper enrichment.

The most important product decision: AI routing. Rather than sending every call to the hosted LLM, I designed two deliberate tiers based on cost vs quality.

Self-hosted LLM
regwatch-llm on Ollama, AWS EC2. Deep contextual understanding of regulatory language. Cost justified by output quality.
Ask bot
Groq free API
Short, fast, low-cost answers for on-demand queries that don't need the full model's depth.

Multi-provider fallback: Ollama → Groq → Anthropic, ensuring uptime if one layer failed. Hosting an LLM on EC2 has real cost. Every call that didn't need that depth shouldn't pay for it.

Feedback and model improvement loop. Every AI-suggested tag and severity classification was surfaced to users as a feedback request. Corrections went through a maker-checker approval flow governed by the Compliance Manager before being accepted, feeding back into the classification model as training signal.

Subscriptions. Any team member can subscribe to alerts and weekly digests filtered by topic and alert severity level.

What I learned

Building RegWatch clarified the gap between a vibe-coded product that works and one that's production-ready. Error handling at scale, observability, graceful degradation when the LLM is slow, access control. These aren't features you add later without real effort.

I now factor this gap explicitly into every spec I write. The difference between something that works and something operationally sound shows up in planning, not in the build.

A PM who has built a full-stack AI product understands the tradeoffs they're asking engineering teams to navigate. That changes the quality of every technical conversation, every PRD, and every scope decision.
